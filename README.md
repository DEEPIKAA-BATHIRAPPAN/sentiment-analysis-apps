# Cloud-Based Sentiment Analysis

**A reusable Python machine-learning package with a Streamlit application**

## Abstract

This project demonstrates a complete, low-cost sentiment-analysis workflow. It
uses TF-IDF to represent text and multinomial Logistic Regression to classify
reviews as Positive, Negative, or Neutral. A reusable `SentimentAnalyzer`
package exposes predictions and class probabilities; Streamlit provides
interactive single-review and batch analysis. The app can be hosted on Streamlit
Community Cloud without paid services, credentials, or API keys.

## Problem statement

Organizations receive large amounts of unstructured feedback. Manually
categorizing it is slow and inconsistent. This project provides a small,
reproducible example of automatically categorizing text, while making the
prediction logic reusable outside the web interface.

## Objectives

- Train and evaluate a three-class text classifier.
- Package inference as a reusable Python API.
- Return a prediction and its model probability, including batch results.
- Provide a web interface for individual reviews and CSV batches.
- Demonstrate a free cloud-hosting path and document its limitations.

## Technologies

Python, pandas, scikit-learn, TF-IDF, Logistic Regression, Streamlit,
matplotlib, pytest, and Streamlit Community Cloud.

## System architecture

**Dataset → TF-IDF → Logistic Regression → Reusable Python Package → Streamlit
Application → Cloud Deployment**

`data/sentiment_data.csv` is validated and split into stratified training and
test sets. Training fits TF-IDF only on training data, evaluates on the held-out
test set, and saves the classifier and vectorizer in
`sentiment_package/models/`. The package loads those artifacts relative to its
own source path, not the shell's current working directory. The Streamlit UI
calls the package for all predictions.

## Dataset

`data/sentiment_data.csv` contains 227 deliberately varied, approximately
balanced starter examples (76 Positive, 76 Negative, and 75 Neutral) with
columns `text` and `sentiment`. This is synthetic,
small-scale starter data intended to demonstrate the workflow, not a
representative production corpus. Model quality depends on the size, diversity,
representativeness, and labelling quality of training data. Replace or extend
it with appropriately licensed, representative examples for meaningful
real-world use.

## TF-IDF and Logistic Regression

Term Frequency–Inverse Document Frequency (TF-IDF) assigns larger weights to
terms that are informative in a document but less common across the corpus.
Unigrams with sublinear term-frequency scaling are used. Logistic Regression learns class decision
boundaries from those sparse features and returns class probabilities with
`predict_proba()`.

## Setup

From the project root, create and activate a virtual environment on Windows
PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e .
```

If PowerShell blocks activation, run commands with
`.venv\Scripts\python.exe` directly instead.

## Train and evaluate

```powershell
python scripts/train_model.py
```

Training validates the two required columns and the three expected labels,
performs an 80/20 stratified split, prints accuracy, precision, recall, F1-score
(via the classification report), and a confusion matrix, then writes two real
artifacts: `sentiment_package/models/sentiment_model.pkl` and
`sentiment_package/models/tfidf_vectorizer.pkl`. These files are generated by
training; they are not placeholders. Rerun training whenever the data or
training code changes.

## Package usage

```python
from sentiment_package import SentimentAnalyzer

analyzer = SentimentAnalyzer()
result = analyzer.predict_with_confidence("I really love this product.")
print(result)
# {
#   "text": "I really love this product.",
#   "sentiment": "Positive",
#   "confidence": 0.0,  # actual value depends on training
#   "probabilities": {"Negative": 0.0, "Neutral": 0.0, "Positive": 0.0}
# }

batch = analyzer.predict_batch(["Excellent service.", "It arrived today."])
```

The displayed numeric values above are illustrative only; actual values are
produced by the fitted model. `confidence` is the `predict_proba()` probability
assigned to the predicted class. It is not the same as accuracy, is not a
guarantee that an individual prediction is correct, and may be poorly calibrated
on data unlike the training set. Empty or whitespace-only text raises
`ValueError`; non-string text raises `TypeError`.

## Tests

Train the model first, then run:

```powershell
python -m pytest
```

Tests cover artifact loading, labels, single and batch results, confidence
bounds, and invalid inputs.

## Streamlit application

Start locally with:

```powershell
streamlit run app.py
```

The application supports a single text review, a multi-line batch, or CSV
upload with a `text` column. Batch output includes each class probability, a
sentiment distribution chart, and a downloadable CSV. The model files must
exist; the app displays a clear training instruction if they do not.

## Evaluation metrics

The training script reports held-out accuracy and per-class precision, recall,
F1-score, support, and confusion matrix. Results depend on the current dataset
and are printed by running training; no fixed score is assumed. A small
synthetic starter set may produce optimistic or unrepresentative results.

## GitHub and cloud deployment

1. Create an empty repository on GitHub.
2. From the project root, initialize Git if needed, add the project files,
   commit them, add the GitHub repository as `origin`, and push the branch.
   Include both generated model files so Community Cloud has trained artifacts.
   Do not commit `.venv/`.
3. Sign in to [Streamlit Community Cloud](https://share.streamlit.io/) with
   GitHub, create an app, select the repository and branch, and set the main
   file path to `app.py`.
4. Community Cloud installs dependencies from `requirements.txt`; wait for the
   app to build and use the generated app URL.
5. To update the app, push commits to the configured GitHub branch. Community
   Cloud will rebuild/redeploy; retrain and commit updated model artifacts when
   training data or code changes.

Streamlit Community Cloud hosts the web application and bundled model files.
This deployment is **not** an Azure Machine Learning deployment. No Azure
credentials, payment details, external API keys, or paid services are required.

## Limitations and future enhancements

- The starter corpus is small and synthetic; it does not capture every domain,
  dialect, sarcasm, or context.
- Probability values depend on the model and data and are not calibrated
  confidence guarantees.
- The current model uses bag-of-words TF-IDF and cannot fully understand word
  order or nuanced context.
- Future work could add a larger appropriately licensed dataset, cross-
  validation, probability calibration, language detection, drift monitoring,
  and a managed model-serving deployment.
